# Persistence acceptance checklist

Implementation gates for the first loop. These tests are **not yet executed**. Use a dedicated ROM and isolated battery-save files; never use the production player's saves. Record ROM SHA-256, engine/compiler versions, save bytes and expected semantic state per test. A whole-emulator save state is not evidence of cartridge persistence.

- [ ] **No save / fresh start:** erased SRAM offers New Game without Continue. Fresh start seeds once; visiting home or changing scenes does not reseed. Opening the title never destroys an existing record.
- [ ] **Expedition cold reload:** leave home, collect the fork and resources, change exposure/view, move Bram and cursor, save, fully stop emulator and boot with only the battery save. Continue restores the expedition, positions, discoveries, knowledge and resource counts; no implicit retreat/extraction or offline time catch-up.
- [ ] **Ownership and intrinsic identity:** record every item ID, intrinsic field and owner; collect/equip/unequip/deposit/withdraw repeatedly with saves between operations. Each live item has exactly one location; equipment references a carried item and still uses capacity. Reload leaves all intrinsic fields byte-identical. Collected objects never respawn through reload or view changes. Duplicate IDs and dangling equipment references are rejected before load.
- [ ] **Capacity at commit:** fill bag while pickup waits; rejected pickup remains available. Full stash allows normal return with excess retained in bag. Repeat with different capacity test constants to avoid embedding provisional six/twelve limits into the format contract.
- [ ] **Safe boundary and queue:** request Save while walking a tile, working the 90-frame harvest, waiting behind jobs, talking, and awaiting return confirmation. No deadlock from a locked menu. Save completes only at the chosen boundary. Cold AND warm Continue restore an idle worker, zero pending count and open admission; no old reward, movement, dialogue or extraction continuation runs. Orders issued after reload work.
- [ ] **Payment exactly once:** invalid/cancelled pulse pays nothing; successful pulse pays once and its remaining benefit survives reload (or Save waits until it finishes). Improvement purchase debits once. If reservations exist, cancellation/refund happens once. Inject Save requests around each debit/result boundary.
- [ ] **Extraction and home:** save before return, after confirmed return, after deposit and after improvement purchase. Continue respects each checkpoint's secured state. Mere saving never secures finds. Repeated doorway travel/reload does not mint shelf reserve or re-credit gathered materials. Test any implemented retreat rule only against its approved loss list.
- [ ] **Interrupted save recovery:** begin with valid record A, then interrupt B after invalidation, metadata, signature, each block boundary, CRC, and before/after final commit. Reboot from resulting SRAM image. Select A or fully committed B, never a mixed snapshot. Repeat writing A while B is newest. Include incomplete first-ever save and repeated failed saves. Byte-cut simulation verifies protocol logic, not physical power-fail guarantees.
- [ ] **Corruption and compatibility:** flip payload, context pointer, header, length, block ID, CRC and commit bytes; reject before any engine state copy. Fall back to previous valid compatible record. With both bad, disable Continue and preserve bytes. Test valid checksum with unsupported schema/build ID, and a rebuilt ROM with changed aliases/scripts; report incompatible, never force-load it. Exercise sequence wrap comparison.
- [ ] **Success/failure reporting:** absent/unwritable/mis-mapped RAM or failed readback must not show Saved. Check explicit Save-and-Quit waits for verified completion. Cancelling a save request does not mutate ownership. Revalidate record size, slot-bank mapping and metadata non-overlap on the final build.
- [ ] **Visual/runtime reconstruction:** restored palette, hidden/collected objects, root connections, equipment effects and paid markers match semantic state; overlay is closed, inputs are rebound once, worker is idle, and music/ambient restart behavior is acceptable. Restore never reopens the boot menu.
- [ ] **Cartridge sign-off, separately authorized:** identify actual save hardware, then test full power-off/restart, retention, real interrupted saves and previous-record recovery on a disposable test save. Measure save feedback/duration. Keep physical results distinct from emulator and browser results.
